# 运维篇：C 盘空间救援（Docker 40GB 数据盘迁移 + junction）

## 一、背景

部署 PentAGI 当天拉完 Kali 沙箱镜像后，C 盘空闲从 30G 直降到 **6.48GB(红)**。元凶：Docker Desktop 的 WSL 虚拟磁盘 `docker_data.vhdx`，**单文件 40.7GB**，躺在 `C:\Users\<you>\AppData\Local\Docker\wsl\disk\`。

## 二、迁移方案选型（含两次试错）

### ❌ 试错 1：改配置键 `DataFolder`
在 `%APPDATA%\Docker\settings-store.json` 加 `"DataFolder": "D:\\Docker\\wsl"` → 重启后**被静默忽略**，Docker 在 C 盘原位置新建了一个空数据盘，`docker images` 全空。

> 教训：Docker Desktop 4.90 的 settings-store.json **不认这个键**（社区旧帖的方法已失效）。版本不同配置 schema 不同，别盲抄。

### ✅ 最终方案：目录联接（junction）
让 C 盘原路径变成一个指向 D 盘的“传送门”，Docker 照常按默认路径读写，实际数据全落在 D 盘。**对 Docker 透明、升级也不怕**。

```bash
# 1) 干净关停（顺序很重要，否则 vhdx 被锁）
"DockerCli.exe" -Shutdown
wsl --shutdown
# 杀掉残留 docker 进程（taskkill docker 相关）

# 2) 整目录搬走（robocopy /MOVE 跨盘=复制后删除，40GB 约 30 秒(SSD)）
robocopy "C:\Users\<you>\AppData\Local\Docker\wsl" "D:\Docker\wsl" /E /MOVE

# 3) 删掉 C 盘残留空壳目录，建 junction（/J 不需要管理员）
rmdir /S "C:\Users\<you>\AppData\Local\Docker\wsl"
mklink /J "C:\Users\<you>\AppData\Local\Docker\wsl" "D:\Docker\wsl"

# 4) 重启 Docker Desktop → docker images 应原样恢复
```

## 三、验证

| 指标 | 迁移前 | 迁移后 |
|---|---|---|
| C 盘可用 | 6.48 GB | ~50 GB |
| 镜像 | — | 5 个全部完好（Kali 20.5GB 等）|
| UI | — | `https://localhost:8443` HTTP 200 |

## 四、其它实测结论

- Windows **宿主机无法直连容器 IP**（172.17.x.x 从宿主机不通），主机侧验证必须走映射端口（如 `localhost:8080`）；容器↔容器直连正常。
- 默认 bridge 网络**不支持 `--ip` 指定静态 IP**（仅 user-defined 网络支持）。
- 发布端口绑 `172.17.0.1` 报 “ports are not available”（Docker Desktop 不允许）。
