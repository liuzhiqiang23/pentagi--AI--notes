# 加固篇：真实主机安全体检与修复

> PentAGI 这类攻击型工具**不适合拿来自动修真机**（定位是评估不是加固、沙箱够不着宿主、也不该让自主 agent 拥有宿主管理员权限）。真机加固的正确姿势是：**工具精准检查 + 人知情批准 + 最小化改动**。本文即当日实操。

## 一、体检清单（全部只读）

```powershell
# Defender 实时防护 / 病毒库时间
Get-MpComputerStatus | Select AMServiceEnabled,RealTimeProtectionEnabled,AntivirusSignatureLastUpdated
# 防火墙三配置
Get-NetFirewallProfile | Format-Table Name,Enabled
# 本机对外监听端口（0.0.0.0 = 全网卡，才是暴露面；127.0.0.1 安全）
netstat -an | findstr LISTENING
# 每个监听端口是谁在听
Get-NetTCPConnection -State Listen | ForEach-Object { $p=Get-Process -Id $_.OwningProcess; ... }
# UAC
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" /v EnableLUA
# SMBv1（永恒之蓝传播面）
Get-SmbServerConfiguration   # EnableSMB1Protocol 应为 False
# RDP 开关
reg query "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections
```

## 二、当日发现与处理

健康项：Defender 开启且病毒库当日更新、防火墙三档全开、UAC 开启、SMBv1 关闭。

**问题 1：MySQL 全网卡监听（高危）**
`3306` + `33060`（X 协议）都听在 `0.0.0.0`——同一 WiFi 任何设备都能尝试连数据库，且 MySQL 安装器自带了一条**防火墙放行 3306 的入站规则**（这就是暴露源）。

修复（双保险 + 留备份）：
```ini
; my.ini 的 [mysqld] 段追加
bind-address=127.0.0.1
mysqlx_bind_address=127.0.0.1   ; X 协议有独立绑定项，bind-address 管不到它！
```
```powershell
# 停用安装器放行的入站规则（block 不如停 allow 干净）
Get-NetFirewallRule ... | Where LocalPort -match '3306|33060' | Disable-NetFirewallRule
# 重启服务
Restart-Service MySQL
```

**问题 2：RDP 处于启用状态**
关闭：
```powershell
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server" /v fDenyTSConnections /t REG_DWORD /d 1 /f
```

## 三、修复后的独立复核（不信日志信实测）

| 复核 | 结果 |
|---|---|
| `netstat -an` 的 3306/33060 | 只剩 `127.0.0.1` 监听 ✅ |
| 被停用的防火墙规则 | Enabled=False ✅ |
| 本地 3306 连通性 | True（本机应用无感）✅ |
| RDP 注册表 | fDenyTSConnections=1 ✅ |

## 四、方法论沉淀

1. **暴露面 = 0.0.0.0 监听的端口**，127.0.0.1 绑定不构成外部风险。
2. 修复动作保持**最小化 + 可回滚**（配置一律先备份：`my.ini.bak-*`）。
3. 提权操作走**一次性 UAC 知情批准**，脚本输出落盘留痕（`*> 文件`）。
4. 一个端口**可能有两个独立配置项**（MySQL 经典端口与 X 协议端口），别只修一半。
5. 攻防工具的定位边界：**让 AI 在隔离靶场里放手打，让受控的人在真机上谨慎改**。
