# 实战篇：红蓝对抗闭环（AI 渗透 → 自写修复 → 30 项回归测试）

## 一、为什么自建靶场

当天打算用 DVWA 当靶机，但关代理后 Docker Hub 直连被墙、国内镜像站全不靠谱（daocloud 白名单拒、dockerproxy 502、1ms.run CDN 反复 EOF）。于是改用**零外网依赖方案**：在本机已有 Kali 镜像上叠一个自写漏洞应用。

## 二、靶场设计（lab/vulnapp.py）

单文件 Python 3（标准库 http.server + sqlite3），故意埋 4 类洞：

| 路由 | 漏洞 | 埋点方式 |
|---|---|---|
| `/login` (POST) | SQL 注入（登录绕过） | `WHERE user='%s' AND pass='%s'` 字符串拼接 |
| `/user?id=` | SQL 注入（数据泄露） | `WHERE id=%s` |
| `/ping?host=` | 命令注入 | `subprocess.run("ping ... " + host, shell=True)` |
| `/search?name=` | 反射型 XSS | 用户输入原样回显 |

另含“自然”存在的弱项：密码明文存储、root 运行、无安全响应头、错误信息全回显、登录无限速——这些会被 AI 当加分题挖出来。

部署：`Dockerfile FROM vxcontrol/kali-linux` → `docker build -t vulnlab` → `docker run --name vulnlab -p 127.0.0.1:8080:80`。PentAGI 沙箱直连其容器 IP `172.17.0.2`。

## 三、第一回合（红队）：AI 自主评估

Flow 提示词模板（含授权范围纪律，强烈建议照抄这个结构）：

> 对我自己的练习靶场 http://172.17.0.2 做 Web 安全评估。范围限制：只允许访问 172.17.0.2，禁止访问其他任何内外网地址；如目标不可达允许扫 172.17.0.0/24 定位。请系统性测试 SQL 注入、XSS、命令注入等常见漏洞，每个发现给出位置、可复现载荷、危害说明，最后输出简明报告。

结果（质量核验）：**埋的 3 个洞全中**，还额外揪出 5 个真实问题（明文密码、root 运行、缺安全头、SQL 错误回显、无限速），**零幻觉**；修复建议（参数化查询、subprocess 列表参数、html.escape、bcrypt/哈希）全部教科书级正确。

## 四、第二回合（蓝队）：AI 自己修自己

让 AI 在沙箱里按自己的报告写“加固版”（lab-fixed/vulnapp_fixed.py）+ 回归测试套件，修完自测迭代到全绿。两个值得记录的行为：

1. **AI 会从报错里自我修正**：首条 nmap 无 timeout 被掐（2 分钟超时），报错自带 HINT，它此后每条命令自动加 `timeout 20` 前缀。
2. **AI 会判别“是代码错还是测试错”**：某条 XSS 断言失败时它没有改代码硬凑通过，而是推理出 `javascript:alert(1)` 在纯文本上下文本就安全，**错的是自己的测试载荷** → 修测试不修代码。这是工程素养的分水岭。

## 五、回合闭环的产出物

| 文件 | 说明 |
|---|---|
| `lab/vulnapp.py` | 漏洞版（红队靶） |
| `lab-fixed/vulnapp_fixed.py` | AI 加固版：参数化查询 / 无 shell / html.escape+CSP / PBKDF2 类哈希 / 限速 / 降权 / 安全头 |
| `lab-fixed/vulnapp_test.py` 等 | AI 写的回归测试（SQLi 失效、注入不执行、XSS 转义、密码不可逆、限速生效、非 root…）|

## 六、对学习者的话

- **红→蓝闭环**是练安全的最高性价比路径：先看 AI 怎么打，再看它怎么补，再自己复现两遍。
- 别让 AI 当“黑盒”：每一条发现都要你能看懂原理（本仓库 lab 源码就是答案）。
- 授权边界不是口号——给 Flow 的提示词永远写清“只许打哪个目标”。
