# 排障篇：代理污染之谜（“全端口开放 + 全是 502”的真相）

> 本文是当日最有价值的一段：**如何用可证伪的对照实验定位“看起来完全正常、其实全假”的扫描结果**。

## 一、现象

PentAGI 沙箱对靶机（`192.168.56.101`）的探测结果诡异到极点：

- `nmap` 显示 **Host is up（0.0037s 延迟）**，80/443/3000/5000/8000/8080/8443/8888 **全部 open**；
- `curl` 任意端口任意 HTTP 方法，**统一返回 `HTTP/1.1 502 Bad Gateway`**（无 Server 头）；
- 而宿主机 `ping` 靶机 **100% 丢包**，宿主 `curl` 则完全超时无响应。

宿主与沙箱看到的世界完全不一样 → 矛盾本身就是线索。

## 二、排查链（重点）

### 第 1 步：别急着信 AI 的“结果”，先怀疑“路径”
AI 扫得很认真，但工具结果的真实性取决于**流量是否真的到达了目标**。先验证网络路径。

### 第 2 步：宿主侧对照实验（权威参照）
宿主 curl **不读系统代理设置**（只读环境变量），所以它是“直连派”：

```bash
curl -sI -m 8 http://192.168.56.101/   # 超时 → 目标其实没有任何响应
```

### 第 3 步：沙箱侧“不存在的主机”实验（一击致命）
如果连**必然不存在的 IP** 都秒回同样的 502，那 502 必然不是目标发的：

```bash
docker exec pentagi-terminal-1 curl -sI -m 8 http://192.168.56.222/   # 也秒回 502！
docker exec pentagi-terminal-1 curl -sI -m 8 http://192.168.56.1/     # 网关也 502
docker exec pentagi-terminal-1 curl -sI -m 8 https://www.baidu.com    # 外网却 200 ✓
```

→ **结论：沙箱到内网网段的流量被某个中间层劫持代答**，而外网正常。

### 第 4 步：找劫持者
- `route print`：默认路由正常（走物理网卡），无异常 0/0 劫持 → 不是 TUN 路由问题？
- `ipconfig /all`：发现 **`Moon365 Meta Tunnel` 虚拟网卡 Up** —— 一个 Clash Meta 内核代理客户端的 TUN。
- 查系统代理：`ProxyEnable=1, ProxyServer=127.0.0.1:7890`。
- **拼图完成**：Docker Desktop 默认“使用系统代理”，把容器所有出站流量送进 Clash(127.0.0.1:7890)。Clash 连 192.168.56.x 这类内网地址失败 → 统一回 502；而 Docker 的代理层在本地就完成了 TCP 握手，所以 nmap 看到的“全端口 open”也是**假握手**。宿主 curl 不吃系统代理 → 看到真实世界（目标根本没在线）。

## 三、修复

```bash
# 1) 关掉残留的系统代理开关（代理程序退出后这个开关还开着会害全网断网）
reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyEnable /t REG_DWORD /d 0 /f
# 2) 广播让浏览器立刻生效
#    InternetSetOption(IntPtr.Zero, 39/37, ...)  # SETTINGS_CHANGED / REFRESH
# 3) 重启 Docker Desktop —— 它会缓存启动时的系统代理配置，不重启仍走死代理
"DockerCli.exe" -Shutdown && 重启 Docker Desktop
```

修复后的复验（必须全过才叫修好）：

| 检验 | 期望 |
|---|---|
| 沙箱 curl 不存在的 172.17.0.222 | **超时**（不再是 502）|
| 沙箱 curl 百度 | 200 |
| 沙箱 curl GLM 端点 | 200 |
| 网页可访问 | 200 |

## 四、可迁移的方法论

1. **现象矛盾时以宿主直连为基准**（不依赖任何代理栈的程序）。
2. **构造“必然为假”的对照组**（不存在的主机/端口），能瞬间区分“目标响应”与“路径假象”。
3. **别放过多网卡/虚拟网卡**：TUN（WireGuard/Clash/Meta/Sing-box 类）会把流量全吸走。
4. 改完代理类配置，**涉及的服务（Docker 等）必须重启**——缓存配置是常态。
5. 顺带教训：`ping 不通 ≠ 主机离线`（靶机防火墙可拦 ICMP 而 TCP 通），`nmap "Host is up"` 比 ICMP 更权威。
